Waffy Escrow Payment lets your shoppers pay through Waffy, an escrow service that holds the buyer's money until the order is confirmed. Instead of funds moving straight from buyer to seller at checkout, Waffy secures them in escrow and releases them to you once the milestone conditions you configure are met — building buyer trust, reducing chargeback exposure, and giving both sides a clear, auditable record of the transaction.

The extension is native, lightweight, and self-contained: the official Waffy PHP SDK is bundled, so a single Composer install pulls in everything the extension needs. It adds Waffy as a payment method on the standard Magento checkout, redirects the shopper to Waffy's secure hosted payment page to pay, and keeps the Magento order in sync automatically through a built-in webhook receiver.

Features

  • Escrow-backed checkout — Waffy appears alongside your other payment methods. The buyer pays on Waffy's secure hosted payment page, and funds are held in escrow rather than transferred immediately.
  • Automatic order status updates — a webhook receiver moves the Magento order to Processing when payment is secured in escrow, and to Complete when the escrow is settled and funds are released. No manual reconciliation.
  • Step-by-step setup — a three-step wizard under Stores > Waffy setup: create your client in the Waffy portal, upload its environment file, and verify. The wizard registers your webhook with Waffy for you.
  • Sandbox environment — run complete test orders against Waffy's sandbox, then go live by connecting a live client through the same wizard.
  • Buyer consent built in — when Waffy needs the shopper's consent, checkout asks for a one-time code sent to their phone, in the same window.
  • Fast checkout — authentication tokens are cached in encrypted form and refreshed by a background cron job, so the shopper waits on the order call only, not on authentication. A live progress indicator keeps them informed while the escrow contract is created.
  • One connection, every store view — the Waffy connection is set up once for the installation, and the checkout title can be changed per website and per store view.
  • Observable — every call to Waffy is written to the Magento system log with its outcome and duration, so support questions are answerable from the log alone.
  • Self-contained — the Waffy PHP SDK ships inside the extension. No additional libraries, and no separate service to deploy.

How it works

  1. The shopper selects Waffy at checkout and places the order. The order is created in Magento with the status Pending Payment. No payment details are requested at this point.
  2. The extension creates an escrow contract with Waffy over a server-to-server HTTPS call and receives a payment URL.
  3. The shopper's browser is redirected to Waffy's hosted payment page, where they enter their payment details and pay.
  4. Waffy holds the funds in escrow and notifies your store. The Magento order moves to Processing.
  5. When the escrow is settled and the funds are released to you, Waffy notifies your store again and the order moves to Complete.

Security

Integration method: redirect only

This extension uses a full browser redirect to a payment page hosted by Waffy. It does not use a direct-post, an API card-capture, an iframe, a hosted field, or any other embedded payment form, and it offers no alternative payment flow. There is exactly one way for a shopper to pay with this extension, and it takes place on Waffy's domain.

Where the customer enters payment data

On Waffy's hosted payment page, never on the merchant site. The extension's checkout component renders only a radio button, the Waffy logo, a short notice that the shopper will be redirected, and the standard Place Order button. It contains no card number field, no expiry field, no CVV field, and no field of any kind that accepts payment credentials. After the order is placed, the shopper's browser leaves the Magento store entirely and lands on Waffy's payment page, where all payment credentials are entered directly into Waffy's environment.

Is cardholder data entered into the Magento server? No

Cardholder data is never entered on, posted to, passed through, or proxied by the Magento server. No payment credentials reach any Magento controller, model, request, or response at any point in the flow. The Magento server never sees a primary account number (PAN), expiry date, cardholder name as printed on the card, CVV, CVC or CID value, magnetic-stripe data, or PIN data.

Is cardholder data stored on the Magento server? No

Nothing resembling cardholder data is written to the Magento database, the file system, the cache, the session, or the log files, because none of it ever arrives. The extension's only database table, waffy_token, holds Waffy OAuth access tokens and nothing else. Those tokens are encrypted at rest with Magento's own EncryptorInterface (AES-256, keyed by the installation's crypt key), and they are not payment instruments: they cannot be used to charge a card, and they carry no cardholder data.

PCI DSS scope and SAQ level: SAQ A

Because every cardholder-data function — capture, transmission, processing and storage — is fully outsourced to Waffy, and because the merchant's Magento server neither receives nor stores cardholder data, a merchant using this extension for e-commerce payments falls under PCI DSS Self-Assessment Questionnaire A (SAQ A), the shortest validation path available to e-commerce merchants. This is the SAQ level defined for merchants who redirect shoppers to a PCI DSS validated third-party payment page. The extension is designed specifically so that installing it does not push a store into SAQ A-EP or SAQ D: no cardholder data element is ever placed within the merchant's cardholder data environment.

What the extension does transmit to Waffy

To create the escrow contract, the extension sends the order reference, the order total and currency, the item names and quantities, the store name, the escrow contract terms (fixed by the extension), and the buyer's first name, last name and mobile number in E.164 format. This is order and contact information required to establish the escrow contract. It contains no cardholder data and no authentication credentials belonging to the shopper.

Transport security

All communication with Waffy — authentication, escrow-contract creation, and the redirect to the payment page — uses HTTPS with TLS certificate verification enabled. Endpoints are fixed to Waffy's own hosts (id.waffyapp.com, auth.waffyapp.com and api.waffyapp.com in production, and the equivalent sandbox hosts in sandbox mode). Plain HTTP is not used anywhere in the payment flow.

Credential storage

Your Waffy API Client Secret and admin password are encrypted with Magento's own encryption key before they are stored — in core_config_data once active, and in an encrypted draft while you are still setting up — and the setup wizard never shows them back. They are never rendered to the storefront, never exposed in JavaScript, and never written to the log.

Webhook endpoint hardening

The inbound webhook endpoint accepts POST only. A webhook can only affect the one Magento order whose stored Waffy milestone identifier matches the payload; an unrecognised identifier is rejected and changes nothing. The endpoint moves an order forward through the payment lifecycle only. It cannot capture funds, issue a refund, alter order totals, or modify customer records.

Logging

The extension logs the sequence and outcome of its Waffy calls to Magento's system log for supportability. Those log entries carry no cardholder data, because none exists on the server to log, and API secrets are excluded from them.

Merchant responsibilities

Serve your storefront and checkout over HTTPS, keep Magento and PHP patched, restrict admin access to the payment configuration section to trusted administrators, and complete the PCI DSS SAQ A questionnaire with your acquirer. Contact Waffy at support@waffyapp.com for the current PCI DSS compliance documentation covering Waffy's hosted payment page.

  • PHP 8.1 and later

Installation

Install with Composer, with no access keys required:

composer require waffy/module-payment
bin/magento module:enable Waffy_Payment
bin/magento setup:upgrade
bin/magento setup:di:compile
bin/magento cache:flush

In production mode, also run bin/magento setup:static-content:deploy -f. A full guide covering Adobe Commerce Cloud and manual or offline installation is included with the extension.

Configuration

You will need a Waffy organization. The setup wizard links to the Waffy portal, where you create it and an API client for your store.

In the Magento admin, go to Stores > Waffy setup, then:

  1. Choose Sandbox for testing and create a client for your store in the Waffy portal.
  2. Upload the client's environment file and enter the client secret and admin password.
  3. Run the checks: the wizard verifies your credentials, registers your webhook with Waffy, and enables the payment method.

Place a test order and pay with Waffy to confirm the flow end to end, then repeat the setup with Live selected to go live.
